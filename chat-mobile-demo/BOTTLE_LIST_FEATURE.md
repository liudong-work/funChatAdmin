# 漂流瓶多选功能更新说明

## 📝 更新内容

### 功能描述
当海洋中有多个可捞的漂流瓶时（至少2个），用户点击漂流瓶图标会弹出一个列表，展示所有可用的瓶子供用户选择。

### 更新时间
2025-10-16

---

## 🔧 技术实现

### 1. 后端 API 更新

**文件**: `backend/src/server-with-db.js`

**端点**: `GET /api/bottle/check`

**更改**:
- 从 `findOne()` 改为 `findAll()`
- 返回最多 5 个可捞的瓶子
- 新增 `limit: 5` 参数

**返回格式**:
```json
{
  "status": true,
  "message": "发现 3 个可捞的瓶子",
  "hasBottle": true,
  "bottles": [
    {
      "uuid": "bottle-uuid-1",
      "message": "瓶子内容1",
      "mood": "开心",
      "created_at": "2025-10-16T..."
    },
    {
      "uuid": "bottle-uuid-2",
      "message": "瓶子内容2",
      "mood": "平静",
      "created_at": "2025-10-16T..."
    }
  ],
  "count": 2,
  "bottle": { ... } // 兼容旧版本，返回第一个瓶子
}
```

### 2. 前端更新

**文件**: `HomeScreen.js`

#### 新增状态:
```javascript
const [availableBottles, setAvailableBottles] = useState([]);  // 存储多个瓶子
const [showBottleListModal, setShowBottleListModal] = useState(false);  // 控制列表弹窗
```

#### 更新的函数:

1. **`checkAvailableBottles()`**
   - 现在处理 `bottles` 数组
   - 保持向后兼容，同时支持单个瓶子和多个瓶子

2. **`handleBottleClick()`**
   - 检测瓶子数量
   - 如果有 2 个或更多瓶子，显示选择列表
   - 如果只有 1 个瓶子，直接捞取

3. **`fishSingleBottle()`**
   - 提取出捞瓶子的核心逻辑
   - 捞取后自动刷新可用瓶子列表

4. **`handleSelectBottle(bottle)`**
   - 处理用户从列表中选择瓶子
   - 关闭列表弹窗并捞取选中的瓶子

#### 新增 UI 组件:

**瓶子列表选择弹窗**:
- 显示瓶子数量
- 滚动列表展示所有可用瓶子
- 每个瓶子显示:
  - 瓶子图标
  - 消息内容（最多2行）
  - 投放日期
  - 箭头指示可点击

### 瓶子列表弹窗样式:
- 白色圆角卡片
- 标题显示瓶子数量（含海浪emoji）
- 副标题提示"选择一个你想要捞取的瓶子"
- 每个瓶子项:
  - 浅灰色背景 (#f8fafc)
  - 圆角设计
  - 瓶子图标 + 消息预览 + 日期 + 箭头
  - 点击时有视觉反馈

### 交互流程:
1. 用户打开主页，看到漂浮的瓶子图标
2. 点击瓶子图标
3. 如果海里有 ≥2 个瓶子：
   - 弹出列表选择界面
   - 用户选择感兴趣的瓶子
   - 系统捞取选中的瓶子
4. 如果只有 1 个瓶子：
   - 直接捞取（保持原有行为）

## 📊 数据库查询优化

**原查询**:
```sql
SELECT * FROM bottles 
WHERE status = 'sea' AND sender_uuid != ? 
ORDER BY created_at ASC 
LIMIT 1
```

**新查询**:
```sql
SELECT * FROM bottles 
WHERE status = 'sea' AND sender_uuid != ? 
ORDER BY created_at ASC 
LIMIT 5
```

**性能影响**: 
- 查询结果集从 1 条增加到最多 5 条
- 数据传输量略微增加（可忽略）
- 用户体验显著提升

## 🔄 向后兼容性

为保持向后兼容，API 响应中同时返回:
1. `bottles` 数组（新）
2. `bottle` 对象（旧）- 指向第一个瓶子

前端代码同时支持两种格式，确保平滑过渡。
